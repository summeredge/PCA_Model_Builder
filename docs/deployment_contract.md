# 部署契约

## 定位与边界

本项目是离线建模与验证工具：建立正常状态模型、独立验证、由工程师执行简单工程冻结，并导出可部署模型包及其计算契约。它不建设在线监控平台，也不建设生产级模型治理平台。

数据中台负责实时数据缓存、按冻结契约进行在线预处理和评分、结果存储及展示。本项目不负责实时数据接入、数据中台接口、数据库、权限系统、企业级后台、model registry、发布审批、父子版本谱系、外部 SHA sidecar、跨进程模型仓库锁或审计级证据链。

## 冻结部署流程（后续实现）

```text
normal_state / candidate
→ 独立验证
→ 工程师确认通过
→ normal_state / validated
→ 工程师简单工程冻结
→ normal_state / frozen
→ 导出可部署模型包
```

冻结必须生成新的冻结模型包，不原地修改已验证模型。`frozen` 仅表示工程冻结，既不是发布审批状态，也不构成完整模型治理生命周期。

## 部署端不变项

数据中台必须使用冻结模型包的固定输入 Tag 顺序、动态特征顺序、预处理参数、均值、标准差、PCA 载荷、特征值、控制限、状态规则和贡献规则。数据中台不得在线重新训练、重新拟合均值和标准差、重新计算 PCA，或修改控制限。

离线端与部署端对相同有效输入必须产生一致的预处理结果、动态特征、PC 得分、T²、SPE、状态、有效性和贡献结果。部署接入的最终验收依据是随冻结模型提供的黄金测试向量；每个向量应覆盖输入、预处理、动态特征、评分、状态、无效原因和贡献。跨实现的数值容差及状态和贡献排名的一致性要求由该测试向量明确。

## 当前状态

当前代码可训练、验证并导出 schema v3 的候选或已验证离线模型包，但尚未实现正式冻结、部署评分参考实现或部署一致性黄金测试。本文定义后续实现与最终部署验收要求，不改变当前运行行为。
