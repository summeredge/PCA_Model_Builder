## 二、术语和职责边界

### 2.1 原始数据检查

原始数据检查针对文件加载后的原始解析结果，只统计问题，不修改数据。

检查内容包括：

* 时间解析、重复、乱序、采样间隔和物理缺口；
* 缺失、非数字、NaN、Inf；
* 全空、无有效数值、恒值和低信息量；
* 报警限超限统计。

原始数据检查不得执行：

* 重采样；
* 无效行删除；
* 平滑；
* Lag；
* 插值或补点。

### 2.2 预处理预览

预处理预览使用当前用户配置，临时展示以下处理结果：

```text
训练窗口选择
→ 按物理段重采样
→ 删除无效数值行
→ 重新划分连续段
→ 因果平滑
→ Lag动态矩阵
```

预处理预览不得修改原始文件，也不得替代正式训练。

### 2.3 无效数值

无效数值是无法转换为有限浮点数的输入，包括：

* 空值；
* 缺失；
* 非数字文本；
* NaN；
* 正 Inf；
* 负 Inf。

无效数值不能参与平滑、Lag、标准化和 PCA，可以在训练预处理中删除对应整行。

### 2.4 工艺异常值

工艺异常值是数值有限，但可能：

* 超过工程量程；
* 超过报警限；
* 偏离正常工况；
* 呈现异常趋势。

工艺异常值不得自动删除、截断、插值或修复。

工程量程和报警限只用于元数据和统计，不直接阻断建模。

## 三、总体衔接方式

### 3.1 保留现有模块职责

| 现有位置               | 后续职责                               |
| ------------------ | ---------------------------------- |
| `data_session.py`  | 统一加载 CSV、XLSX、TXT，保存文件元数据、读取参数和列缓存 |
| `quality.py`       | 只执行原始数据客观检查，不修改数据                  |
| `/api/inspect`     | 用户手动触发原始数据全量检查                     |
| `tag_config.py`    | 保存 Tag 角色、报警限、工程量程和忽略状态            |
| `preprocessing.py` | 重采样、无效行删除、连续段重建、因果平滑和动态矩阵处理        |
| `training.py`      | 多窗口独立预处理并合并训练矩阵                    |
| `dpca.py`          | 保持 Z-score 和 PCA 拟合逻辑              |
| `model_io.py`      | 保存和校验完整预处理配置、Tag 顺序和训练摘要           |
| 验证和评分模块            | 使用模型包固定参数重放，不重新推断或覆盖               |
| 发布模块               | 保持模型生命周期和部署包边界不变                   |

### 3.2 不进行的结构调整

本轮不实施：

* 独立的数据预处理子项目；
* 新工作流或状态机；
* DPCA、T²、SPE、贡献和验证算法迁移；
* 为概念阶段划分而重构 Lag 调用链；
* 去趋势、差分、移动中位数或其他新滤波器；
* 自动噪声判断；
* 变量级重采样或平滑参数；
* 插值、补点或自动异常值修复；
* 新页面；
* 模型生命周期调整。

现有 `fit_dpca()` 中的 Z-score、`mean`、`scale` 和 PCA 拟合逻辑继续复用。

## PR-11：冻结数据检查与预处理契约

### 目标

### 契约内容

固定正式训练流程：

```text

→ 用户手动执行原始数据检查
→ 用户确认忽略变量
→ 选择训练窗口
→ 按窗口和物理段全局重采样
→ 对建模Tag和状态过滤列转换数值
```

固定以下规则：

* 原始数据检查不修改数据。

* 无效数值与工艺异常值使用不同语义。

  * 本次实际建模 Tag；

* 相邻时间戳间隔不符合当前重采样间隔时，必须形成新的连续段。

* 连续段判断优先复用项目已有采样间隔容差，不新增冲突规则。

* 窗口边界、物理缺口和无效行删除形成的断点必须重置平滑与 Lag 上下文。

* 新模型只允许：

  * `none`；
  * 一阶滤波；
  * 尾随移动平均。

* 旧模型中的历史滤波方法只允许按原语义兼容读取和评分，不重新暴露为新模型选项。

* 标准化固定使用训练模型中的 Z-score 参数。

* 验证、模型重放和 CLI 评分不得重新推断预处理参数。

冻结训练摘要结构，至少包括：

```text
  output_rows
```

### 修改边界

不修改生产代码。

### 验收

## PR-16：无效数据整行删除语义

### 目标

将无效值处理改为正式、可统计、不可跨段的整行删除流程。

### 主要修改

* `src/pca_model_builder/preprocessing.py`
* `src/pca_model_builder/training.py`
* `tests/test_preprocessing.py`
* `tests/test_training.py`
* 必要时调整 `tests/test_quality.py`

### 处理顺序

每个训练窗口和每个物理段独立执行：

```text
重采样
→ 对建模Tag和状态过滤列转换数值
→ 标记包含任一无效数值的行
→ 删除整行
→ 按剩余时间戳重新划分连续段
→ 平滑
→ Lag
```

### 连续段规则

删除无效行后：

* 相邻时间戳间隔符合当前重采样间隔时，属于同一连续段；
* 相邻时间戳间隔不符合当前重采样间隔时，必须建立新段；
* 使用项目已有时间间隔容差；
* 不允许平滑或 Lag 跨越新形成的断点。

### 关键边界

* 无效行删除不得跨窗口影响其他窗口。
* 不插值、不补点。
* 未参与本次建模的列有无效值时，不得删除样本。
* 原始数据检查继续报告删除前的问题数量。
* 训练只在删除和预热损失后有效样本不足时失败。
* 不得使用全表有限值掩码替代建模列范围判定。

### 损失摘要

每个窗口记录：

* 删除前行数；
* 重采样后行数；
* `invalid_row_loss`；
* 删除后形成的连续段数；
* 平滑预热损失；
* Lag 预热损失；
* 最终动态矩阵行数。

总摘要必须等于各窗口摘要之和。

### 修改边界

* 不改变重采样算法。
* 不改变滤波算法。
* 不改变 Lag 特征命名、顺序和方向。
* 不改变 Z-score、DPCA、T²、SPE 和贡献计算。

### 验收

* 任一建模 Tag 出现非法值时，对应时间点从所有建模 Tag 中整行删除。
* 删除点前后的平滑和 Lag 不串联。
* 未选择 Tag 的非法值不影响训练。
* 多窗口损失汇总与实际动态矩阵行数一致。
* 原始数据检查统计不被训练删除结果覆盖。
* 全量测试通过。

## PR-17：平滑算法、配置与模型包语义

### 目标

实现固定的两种新模型平滑算法，并保证新旧模型均可按自身固定语义重放。

### 主要修改

* `src/pca_model_builder/preprocessing.py`
* `src/pca_model_builder/model_io.py`
* 必要的模型版本兼容检查模块
* `tests/test_preprocessing.py`
* `tests/test_model_io.py`
* 对应模型兼容和评分测试

### 新模型支持

#### 一阶滤波

固定因果公式：

```text
y[t] = α × x[t] + (1 - α) × y[t-1]
```

规则：

* `0 < α ≤ 1`；
* 每个连续段首个有效值使用原始值初始化；
* 窗口边界、物理缺口和无效行删除断点必须重置；
* 不产生额外预热损失。

#### 尾随移动平均

规则：

* 只使用当前时刻及历史数据；
* 窗口参数使用分钟；
* 根据重采样间隔换算为行数；
* 只在完整窗口可用时输出；
* 每个连续段独立计算；
* 不允许跨段补足窗口。

### 新模型配置

模型包字段：

```text
filter_method
smoothing_window_minutes
first_order_alpha
```

其中：

* `filter_method = none | first_order | trailing_mean`
* `first_order_alpha` 仅在 `first_order` 时有效；
* `smoothing_window_minutes` 仅在 `trailing_mean` 时有效；
* 无关参数必须为空或按照契约固定值保存，不得产生歧义。

### 旧模型兼容

### 修改边界

# 六、实施范围结论

本轮仍建议拆分为 8 个 PR，但主线不再被 TXT 样例阻塞。

新增生产能力限定为：

2. 只检查、不修改数据的原始数据检查；
3. 推荐忽略和人工忽略管理；

5. 全局一阶滤波和尾随移动平均；

* 多窗口训练；
* Z-score；
* DPCA；
* T² 和 SPE；
* 贡献计算；
* 验证指标；
* 模型比较；
* 模型生命周期；
* 发布和部署边界。

本轮不扩大为通用数据清洗平台，也不改变 PCA_Model_Builder 的离线建模、验证和冻结模型包定位。
