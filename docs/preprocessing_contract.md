# 预处理契约

## 基本原则

离线训练、验证、冻结回放和未来部署必须保持相同预处理语义。本文冻结后续 PR 的实现边界；本 PR 仅更新契约，不改变当前计算、页面或模型包格式。

- 时间戳必须可解析、递增、唯一。
- 必须识别物理时间缺口；滤波和 Lag 不得跨越物理缺口或删除无效行后重新建立的连续段边界。
- 滤波必须为因果计算。
- 不自动插值、补点或修改异常值。

## 基础数据检查与训练预处理

基础数据检查与正式训练预处理是两条独立流程，保留现有“基础数据检查”和“建模质量检查”分离的语义：

```text
文件加载
→ 原始/基础数据检查
→ 用户确认 Tag 配置和忽略变量
```

`/api/inspect` 对应的基础数据检查基于上传后原始解析数据。它不执行重采样、无效行删除、滤波或 Lag，不依赖训练预处理参数，只报告问题而不修改数据。检查可报告缺失、非数字、NaN、Inf、常量、全空、量程/正常范围/报警限越界等信息；工程量程、正常范围和报警限越界均不得自动裁剪、替换或修改数据。精确常量、全空或无有效数值的变量可产生“建议忽略”，最终是否忽略必须保留人工确认语义。

正式训练预处理在训练窗口选择后执行；建模质量检查可使用已确认的 Tag、训练窗口和训练配置，但不得与上述原始/基础数据检查重新合并。后续实现必须按以下顺序执行，且不能以其他步骤替代其中的删除和重新分段语义：

```text
训练窗口选择
→ 物理缺口识别
→ 重采样
→ 数值转换
→ 删除无法参与计算的无效整行
→ 按剩余时间戳重新识别连续段
→ 因果滤波
→ Lag扩展
→ 删除预热/上下文不足数据
→ Z-score
→ DPCA
```

重采样后，缺失、非数字、NaN、Inf 等无法参与数值计算的行可统一删除，不再要求这些行直接阻断训练。删除后出现的时间断点必须按剩余时间戳重新建立连续段，因果滤波和 Lag 均不得跨段取历史或上下文。评分上下文不足、滤波预热或缺口重置期间不得伪造评分结果。

训练继续复用现有独立训练窗口，以及 `window_summaries` 和 `training_window_totals` 作为唯一训练窗口统计体系；后续功能不得另建重复统计体系。

## 平滑模式与历史兼容

后续新建模型的默认平滑模式为 `none`。支持的目标语义为：

- `none`：不做平滑。
- `first_order`：一阶因果滤波，参数为 `first_order_alpha`，且必须满足 `0 < alpha <= 1`。
- `trailing_mean`：现有尾随移动平均。

`trailing_median` 只保留为旧模型读取兼容，不得作为后续 Web 新建模型的选项。

旧模型若缺失 `filter_method`，必须按历史 `trailing_mean` 解释；不得因新的 `none` 默认值重新解释旧模型。当前 schema 4 / deployment schema 1 必须继续按其历史预处理语义加载和回放，不得被“先删除无效行并重新分段”等新规则重新解释。模型加载、冻结回放和部署均必须使用包内固定预处理字段和对应 schema 语义，而不是当前软件默认值。

一阶滤波在每个删除无效行后形成的连续物理段的首个有效样本初始化状态。验证、冻结回放和部署不得通过任意固定分钟数截断历史后重新初始化；同一段完整输入在不同回放起点下不得产生不同特征。冻结、部署和回放必须采用完全相同的连续段重置与初始化语义。

## Tag 量程与报警字段兼容

现有 Tag 角色以及 `engineering_min/max`、`normal_min/max`、`alarm_min/max` 的字段含义保持不变。后续若支持 LL/L/H/HH，必须新增独立、可选字段，例如：

- `alarm_ll`
- `alarm_l`
- `alarm_h`
- `alarm_hh`

不得把现有 `alarm_min/alarm_max` 静默重新解释为 LL/HH 或 L/H。旧 Tag 配置、Excel 导入导出和模型包读取必须保持兼容。

## 后续 Web 实现边界

正式 Web 继续使用现有五阶段工作台和 `web_model_results.py` 的 field-anchor/单一控件组装机制。后续新增 `firstOrderAlpha` 等字段必须拥有唯一 ID，并沿用 `_stabilize_workbench_html()` 的现有扩展方式。

不得复制已有参数 HTML，也不得建立第二套重采样、滤波、预处理预览或数据检查入口。PR14/PR18 应扩展当前“基础数据检查”和现有全局预处理配置，而不是重新建立页面体系。
