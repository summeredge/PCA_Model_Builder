# 预处理契约

## 适用范围

本契约定义未来冻结模型在离线端和数据中台必须共享的预处理语义。当前代码已实现尾随平滑和 Lag 扩展；重采样、扩展滤波和统一部署参考实现属于后续计划。

## 固定规则

- 时间戳必须可解析、排序递增且唯一；输入 Tag 必须满足冻结模型的固定顺序。
- 原始物理时间缺口必须在重采样前识别。每个物理连续段独立预处理，重采样、滤波和 Lag 都不得跨物理缺口。
- 滤波必须是因果尾随算法，不得读取未来数据。
- 不同训练窗口独立处理，不得共享滤波或 Lag 上下文。验证或在线评分可以读取评分点前的历史上下文，但该上下文不得计入评分或训练结果。
- 默认不自动插值、补点或删除异常值；任何此类行为必须由冻结参数明确规定。
- 固定执行顺序为：时间戳解析与重复/乱序检查 → 原始物理缺口识别 → 连续段内重采样 → 空时间桶检查 → 数值和工程量程检查 → 因果滤波 → 状态过滤 → Lag 扩展 → 删除预热不足行 → 使用参考状态均值和标准差进行 Z-score → DPCA 评分。
- 数据中台必须使用冻结模型保存的相同预处理参数和重置规则，不能自行替换默认值。

单时刻评分所需的最小前置上下文为：

```text
max_lag + smoothing_or_filter_window - sample_interval
```

上下文不足或物理时间缺口后的重新预热期间，该点不可评分。
